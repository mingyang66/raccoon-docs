Java record是在Java14中引入的预览特性，并在Java16中正式成为标准语言特性，它是一种轻量级的类声明方式，专门用于创建不可变的数据载体（Data Carrier），比如DTO（数据传输对象）、值对象或临时数据结构等。

RecordBuilder:[https://github.com/randgalt/record-builder](https://github.com/randgalt/record-builder)

官方文档：[[JEP 395: Records](https://openjdk.org/jeps/395)]([JEP 395: Records](https://openjdk.org/jeps/395))

Maven依赖管理：

```
<dependencies>
    <dependency>
        <groupId>io.soabase.record-builder</groupId>
        <artifactId>record-builder-core</artifactId>
        <version>${record.builder.version}</version>
        <scope>provided</scope>
    </dependency>
</dependencies>
<!--显式告诉Java编译器（javac）在编译阶段加载并执行record-builder-processor注解处理器-->
<build>
    <plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <configuration>
                <annotationProcessorPaths>
                    <path>
                        <groupId>io.soabase.record-builder</groupId>
                        <artifactId>record-builder-processor</artifactId>
                        <version>${record.builder.version}</version>
                    </path>
                </annotationProcessorPaths>
            </configuration>
        </plugin>
    </plugins>
</build>
```

###### 一、为什么需要record-builder-processor

Java record 虽然能自动生成基础的 getter、equals 等方法，但原生并不支持 Builder 模式。RecordBuilder 就是一个通过注解处理器（APT）来解决这个问题的工具。
当你在代码中使用 @RecordBuilder 注解时，这个处理器会在内存中扫描源码，并为你的 record 自动生成对应的 Builder 类（例如 XxxRecordBuilder.java）。如果不配置 <annotationProcessorPaths>，Maven 编译器可能无法正确识别并激活这个处理器，导致在执行 mvn compile 时报出类似 cannot find symbol: class XxxRecordBuilder 的编译错误。

###### 二、为什么不直接写在 dependencies 里？

在现代 Java 开发中，Maven 默认不再自动把 classpath 中的所有依赖都当作注解处理器来执行。
<dependencies>：只是把 jar 包下载到本地并加入项目的运行/编译类路径。
<annotationProcessorPaths>：是专门为编译器指定的“处理器白名单”。它明确隔离了编译期工具和运行期依赖，确保编译器知道去哪里找这些处理器。
