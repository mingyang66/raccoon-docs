RSA/ECB/PKCS1Padding是Java Cryptography Architecture(JCA 加密体系结构)中用于指定RSA加密算法、工作模式和填充方案的标准转换字符串（Transformation String）。

##### 一、组成部分解析

- RSA：算法名称。表示使用非对称加密算法RSA。

- ECB：工作模式（Electronic Codebook）。
  
  注意：RSA是一种块加密算法，但它的块大小由秘钥长度决定（例如：2048位秘钥对应256字节块）。与AES等对称加密不同，RSA实际上并不支持真正的ECB、CBC等模式。
  
  在Java的JCA规范中，对于RSA算法，中间的模式部分通常被忽略。无论你写RSA/ECB/...还是RSA/None/...，效果是一样的。写成ECB只是为了符合Algorithm/Mode/Padding的通用格式习惯，或者是为了兼容某些旧代码。

- PKCS1Padding：填充方案。表示使用PKCS#1 v1.5标准的填充方式。这是RSA最传统且广泛支持的填充标准。

        它会在加密前向数据中添加随机字节，防止相同的明文每次加密都生成相同的密文（提         供了一定的语义安全性），并防止某些简单的数学攻击。

##### 二、代码示例

```
import javax.crypto.Cipher;
import java.security.KeyPair;
import java.security.KeyPairGenerator;
import java.security.PrivateKey;
import java.security.PublicKey;

public class RSAExample {
    public static void main(String[] args) throws Exception {
        // 1. 生成密钥对 (2048位)
        KeyPairGenerator keyGen = KeyPairGenerator.getInstance("RSA");
        keyGen.initialize(2048);
        KeyPair keyPair = keyGen.generateKeyPair();
        PublicKey publicKey = keyPair.getPublic();
        PrivateKey privateKey = keyPair.getPrivate();

        // 2. 获取 Cipher 实例
        // 字符串格式: "算法/模式/填充"
        // 注意：这里的 "ECB" 对 RSA 无效，但必须填写以符合格式，通常写 "ECB" 或 "None"
        Cipher cipher = Cipher.getInstance("RSA/ECB/PKCS1Padding");

        // 3. 加密
        String plainText = "Hello, RSA!";
        byte[] data = plainText.getBytes("UTF-8");
        
        cipher.init(Cipher.ENCRYPT_MODE, publicKey);
        byte[] encryptedData = cipher.doFinal(data);
        
        System.out.println("加密完成，密文长度: " + encryptedData.length + " 字节");

        // 4. 解密
        cipher.init(Cipher.DECRYPT_MODE, privateKey);
        byte[] decryptedData = cipher.doFinal(encryptedData);
        
        String result = new String(decryptedData, "UTF-8");
        System.out.println("解密结果: " + result);
    }
}
```

##### 三、关键特性与限制

###### A.数据长度限制

由于PKCS#1 v1.5填充需要占用至少11个字节的开销（包括随机数和分隔符），因此RSA加密的明文长度收到秘钥长度的严格限制：

- 最大明文长度=（秘钥长度/8）-11字节。

- 例如：

            1024位秘钥：最大加密（1028/8）-11 = 117字节。

             2048位秘钥：最大加密（2048/8）-11 = 245字节。

              4096位秘钥：最大加密（4096/8）-11 =501字节。

- 如果数据超过这个长度，cipher.doFinal()会抛出IllegalBlockSizeException。通常需要结合对称加密或使用分段加密来解决昌数据加密问题。

###### B.安全性警告

虽然PKCS1Padding(即PKCS#1 v1.5)仍然被广泛使用且在很多场景下被认为是安全的，但它存在已知的理论弱电：

- CCA2攻击适应性：注明的Bleichenbacher攻击（1988）展示了如果服务器对填充错误的响应不同（例如：返回不同的错误码或耗时不同），攻击者可以通过数百万次查询解密文或伪造签名。

- 现代替代方案：在新系统中，强烈推荐使用OAEP填充（RSA/ECB/OAEPWithSHA-256AndMGF1Padding）。OAEP（Optimal Asymmetric Encryption Padding）提供了更强的安全性证明，能抵抗适应性选择密文攻击。

##### 四、总结建议

| 特性       | 说明                                                                                |
| -------- | --------------------------------------------------------------------------------- |
| 全称       | `RSA/ECB/PKCS1Padding`                                                            |
| 用途       | 传统的 RSA 非对称加密                                                                     |
| 模式 (ECB) | 对 RSA 无效，仅作为占位符                                                                   |
| 填充       | PKCS#1 v1.5 (随机填充，需 11 字节开销)                                                      |
| 优点       | 兼容性极好，几乎所有语言和库都支持                                                                 |
| 缺点       | 有已知侧信道攻击风险；明文长度受限严重                                                               |
| 最佳实践     | 新项目建议使用 OAEP (`RSA/ECB/OAEPWithSHA-256AndMGF1Padding`)。仅在需要兼容旧系统时使用 PKCS1Padding。 |
